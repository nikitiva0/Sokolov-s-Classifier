# Как нейросеть представляет Евгения Соколова

Учебный проект: обучить бинарный классификатор присутствия Евгения Соколова,
проверить его на независимых фотографиях и оптимизировать изображение из шума,
максимизируя оценку класса «Соколов».

**Зафиксированы две модели: ResNet18 и ArcFace. Обе обучаются только
на выделенных и выровненных лицах (`face_crop`).**
У датасета есть train/test; validation выделяется только из train.

**Текущий статус — архитектура и каркас.** Проверка конфигураций работает.
Подготовка данных, обучение, оценка и синтез пока представлены интерфейсами;
обученных весов и измеренных результатов в репозитории нет.
Добавлен [позитивный набор из 1000 кропов веб-камеры](data/raw/sokolov_positive_v1/README.md)
для последующего выделения лиц; негативные примеры и разбиение ещё не подготовлены.

## Модели и эксперименты

| Модель | Backbone / исходные веса | Вход | Данные | Конфиг |
| --- | --- | --- | --- | --- |
| ResNet18 | Torchvision ResNet18 / ImageNet `IMAGENET1K_V1` | 224 × 224 | Лицо | `configs/resnet18_face.toml` |
| ArcFace | InsightFace `arcface_torch`, iResNet50 / MS1MV3 | 112 × 112 | Лицо | `configs/arcface_face.toml` |

ArcFace — функция потерь, с которой предобучен выбранный лицевой encoder,
а не название отдельной архитектуры. В этом проекте «ArcFace» означает
**iResNet50, предобученную на MS1MV3 с ArcFace**, и бинарную голову
`Linear(512, 1)` после L2-нормализованного эмбеддинга.
Для обучения обеих бинарных голов используется `BCEWithLogitsLoss`.

Перед подачей в любую модель выделяем и выравниваем лица.
Для сравнения моделей используем одни и те же face crops, исходные фотографии
и сохранённое групповое разбиение.

## Данные и разбиение

Исходный CSV содержит `partition=train|test`. Проверяем общие съёмки и дубликаты
между train/test до любых преобразований. Из внешнего train по группам выделяем
около 20% для validation (`seed=42`); внешний test не перераспределяем.
Конкретные назначения исходных фотографий сохраняем **один раз** и используем
для обеих моделей. Лицо наследует split исходного кадра.

Пример организации локальных файлов:

```text
data/raw/train/{positive,negative}/...
data/raw/test/{positive,negative}/...
data/manifests/raw.csv
data/processed/face_crop/{train,val,test}/...
```

Источником истины служат манифесты, а не имена папок.
Правила разметки и схемы CSV: [data/README.md](data/README.md).

## Проверка каркаса

Python 3.11+. Из корня проекта, без установки ML-библиотек:

```bash
PYTHONPATH=src python3 -m sokolov check-config --config configs/resnet18_face.toml
PYTHONPATH=src python3 -m sokolov check-config --config configs/arcface_face.toml
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Без `--config` проверяется `configs/resnet18_face.toml`.
Проверка конфигурации не требует существующего датасета и весов; она не
подтверждает готовность обучения. Других исполняемых CLI-этапов пока нет.

Для разработки:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
```

Общие зависимости будущей ML-реализации: `python -m pip install -e '.[ml]'`.
Для ArcFace дополнительно предстоит подключить PyTorch-backbone из официального
`arcface_torch` с фиксацией версии исходников и локального checkpoint
`checkpoints/arcface/iresnet50_ms1mv3.pt`. Этот адаптер пока не реализован;
установка extra `ml` сама по себе ArcFace не подключает.
Автоматической загрузки весов нет. В артефактах будущего запуска сохраняем их SHA-256.

Для синтеза обе модели должны работать в PyTorch с градиентом по входу.
ONNX Runtime не используется в тракте градиентной оптимизации.
Совместимые версии библиотек и сборку PyTorch под CPU / CUDA / MPS зафиксируем
при реализации. Сейчас lock-файла нет.

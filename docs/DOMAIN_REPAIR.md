# Обучение без подсказок от источника фото

Изменение кода и локального датасета от 31 октября 2026. Новый запуск обучения
не выполнялся. Существующий UI по умолчанию использует прежние веса `local-mps-v2`;
изменение кода не исправляет уже обученную модель автоматически.

## Что изменено

- `model.face_preprocessing="identity_v1"`: после выравнивания остаётся овальная
  область лица; остальное заполняется серым. Цвет переводится в яркость, среднее
  и контраст внутри маски нормализуются. Обеим меткам задаётся одинаковая
  эффективная сетка 56×56 с восстановлением размера 224/112. Это уменьшает
  различия цвета, освещения, фона и разрешения веб-камеры/FairFace.
- `training.augmentation="robust"`: отражение, поворот до 6°, небольшой сдвиг
  и масштаб, изменение яркости/контраста/цвета, уменьшение разрешения, размытие,
  JPEG-сжатие. Одна и та же случайная процедура для обоих классов, только train.
  Validation, test, UI и генерация используют одну детерминированную обработку.
- `training.source_balanced=true`: при выборе train-примеров уравнивается масса
  лекционных и интернет-источников внутри класса, затем отдельных источников.
  Несколько новых портретов не теряются среди тысячи кадров одной обстановки.
  Суммарное соотношение классов сохраняется; `pos_weight` берётся только из train.
- `split.mode="group_stratified"`: одна лекция/съёмка целиком попадает в один split.
  Источники, связанные pHash-кандидатами, объединяются до разбиения. Картинки не
  удаляются только по pHash. Цель — примерно 70/15/15 с двумя классами везде;
  из-за целых лекций точные доли и размеры 4200/900/900 не гарантируются.
  Если достаточно независимых интернет-групп, val и test получают минимум по две
  группы каждой метки. Число интернет-фото и групп записывается в аудит.
- `training.selection_metric="source_macro_ap"`: checkpoint и архитектура
  выбираются по среднему validation AP для лекционных и интернет-позитивов.
  Каждый домен сравнивается с теми же validation-негативами. Порог выбирается
  по F1 на validation с весами источников внутри класса. Test не участвует.
  Общий AP также сохраняется. Отчёт отдельно показывает интернет-позитивы и
  лекционные позитивы против общего набора негативов.

Маска геометрическая, а не сегментация кожи; неоднородное освещение и все признаки
источника она не устраняет. Сетка 56×56 — фиксированный параметр новой политики,
который также может уменьшить полезную детализацию. Эффект нужно измерить после
обучения. Для старых checkpoint без новой настройки сохраняется прежняя RGB-обработка.

Полный список страниц, URL изображений, меток, групп, контрольных сумм и координат
пользовательских кропов: `data/sources/domain_v3_sources.json`.

Дубликаты и неоднозначная детекция могут уменьшить итоговое число.

Локальные файлы: `data/raw/sokolov_domain_v3/` и
`data/manifests/domain_v3/web.csv`. В Git включается каталог источников, а изображения
и рабочий CSV игнорируются. У публичных страниц не установлена единая лицензия
на изображения; локальный архив для эксперимента следует держать приватным.

## Восстановление данных без обучения

Из корня проекта с зависимостями:

```sh
.venv/bin/python tools/build_domain_dataset.py --user-photo-dir /path/to/originals
```

При наличии проверенных локальных копий сеть не используется. При отсутствии
публичные файлы скачиваются по каталогу, пользовательские пять берутся из указанной
папки с исходными именами. Контрольные суммы защищают от замены изображений.
Если пользовательских оригиналов на другой машине нет, явно используйте
`--skip-user-photos`: получится дополнение из 17 публичных фото. Это другой датасет,
для него нужен новый raw/prepared каталог и новый запуск.

Дополнительные свои снимки можно включить через CSV `data.extra_manifest` с полями
`image_id,path,label,source_id,source_url`. Разные обработки одной съёмки должны
иметь общий `source_id`; для интернет-фото используйте префикс `web:`. На групповом split требуется достаточно независимых
источников обоих классов. Маленькие val/test по интернет-портретам дают нестабильные
оценки; для уверенной проверки нужны новые независимые фото, не использованные при разработке.

`tools/package_kaggle.py` включает дополнение из CSV в приватный `work/project_bundle.zip`.
Оригиналы с посторонними людьми, внутренние файлы аудита, веса и секреты не включаются.

## Следующий запуск — вручную

Локальные конфиги используют `device="mps"`; ноутбук сохраняет новый запуск в
`outputs/runs/domain-mps-v3/`. Старые данные и веса v2 остаются отдельными.
Не продолжайте v2 с новой конфигурацией: изменились входы, выборка и критерий отбора.
При необходимости можно задать `reuse_prepared_manifest` в обоих TOML на старый
`data/processed/local_mps_v2/manifest.csv`: переиспользуются только проверенные кропы
с совпавшими пикселями, меткой и детектором, а split формируется заново.

После самостоятельного завершения обучения UI подключается командой:

```sh
.venv/bin/python tools/serve_ui.py --run-dir outputs/runs/domain-mps-v3 --device mps
```

Автоматическое объединение pHash не доказывает отсутствие всех похожих фото.
Личности FairFace по-прежнему не гарантированно изолированы. Генеративные варианты
одного лица не заменяют новые реальные съёмки. Старые высокие метрики случайного
split нельзя использовать как подтверждение качества этой версии.

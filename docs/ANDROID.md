# «Классификатор Соколова» для Android

Целевой телефон — Samsung Galaxy A35. Приложение выполняет поиск лиц и классификацию на устройстве, без сервера. Модели загружаются отдельным ZIP после завершения обучения. В APK нет случайных «готовых» весов и он не выдаёт результат без установленного комплекта.

## Реалистичная скорость

Для камеры разумный первый ориентир — 5 проверок/с с ResNet18 и одним крупным лицом. 10/с — цель для проверки, не измеренный результат. Exynos 1380 и наличие NPU не гарантируют ускорение конкретного ONNX-графа; текущая реализация использует XNNPACK на CPU, 4 потока. ArcFace iResNet50 существенно тяжелее и может быть медленнее. Приложение показывает фактическое время детекции, классификации всех лиц, всего кадра и частоту результатов. Несколько лиц увеличивают время классификации, нагрев снижает устойчивую скорость.

Камера анализирует только свежий кадр, без очереди старых кадров; максимальная частота запуска — 10/с. В этой простой версии на экран выводится именно обработанный кадр с рамками, поэтому видимая частота совпадает с частотой анализа. Несовпадающие во времени рамки поверх более свежего видео не рисуются.

FP32-веса ResNet18 занимают примерно 43 MiB, ArcFace iResNet50 — около 160 MiB, плюс SCRFD и runtime. Точные размеры выводятся при экспорте. Оба классификатора хранятся на телефоне, но открыт только выбранный. Квантование/замена детектора могут ускорить и уменьшить комплект, однако требуют новой проверки качества и не применяются молча.

Источники: [Samsung о телефонах с Exynos](https://semiconductor.samsung.com/processor/showcase/smartphone/), [рекомендации ONNX Runtime Mobile](https://onnxruntime.ai/docs/tutorials/mobile/), [CameraX image analysis](https://developer.android.com/media/camera/camerax/analyze).

## 1. Сохранение лучших весов

Для каждой модели сохраняются независимо:

- `resnet18/best.pt`, `arcface/best.pt` — лучшие checkpoints по validation AP, с конфигурацией;
- `resnet18/best_weights.pt`, `arcface/best_weights.pt` — соответствующие чистые state_dict;
- `last.pt` — продолжение обучения, не используется вместо best при мобильном экспорте;
- `threshold.json` — validation-порог, привязанный к SHA-256 best.pt.

`best_model.pt` остаётся общим победителем для генерации из шума. На телефон экспортируются **обе** лучшие модели, а не только общий победитель.

## 2. Экспорт после Kaggle-обучения

Установленные `requirements-kaggle.txt` уже включают onnx и onnxruntime. Из корня проекта:

```bash
python -m sokolov export-mobile \
  --run-dir /kaggle/working/runs/fairface5000_seed42_v1 \
  --output /kaggle/working/mobile_models.zip
```

При необходимости передайте `--detector /path/to/det_10g.onnx`. Нужен тот же SCRFD, который использовался при подготовке: экспорт сверяет его SHA-256 с аудитом. Детектор не скачивается с произвольного источника при импорте.

Команда строго загружает оба best.pt, проверяет привязку порогов и совпадение split. Экспортирует классификаторы с нормализацией внутри ONNX: вход RGB NCHW float32 [0,1], выход — оценка класса «Соколов». Проверяет ONNX и сопоставляет предсказания с PyTorch на трёх входах, допуск 1e-4. В ZIP попадают только manifest.json, два классификатора и detector.onnx; конфиги с локальными путями, обучающие фото, токены и исходные .pt не включаются.

Обычный экспорт запрещён для технических случайных весов. Флаг `--allow-technical` существует только для разработки; такой комплект помечается заметным предупреждением в приложении и не считается проверкой личности.

Скачайте ZIP через Kaggle Output на Galaxy A35. Для уже запущенного старого обучения без чистых best_weights.pt достаточно best.pt: мобильный экспорт работает с полным checkpoint.

## 3. Установка и использование

Установите собранный `app-debug.apk` на телефон, разрешив установку из выбранного файлового менеджера. Это отладочная сборка для личного тестирования, не публикация в Google Play.

1. Откройте «Классификатор Соколова».
2. Нажмите «Загрузить модели (.zip)», выберите mobile_models.zip. Импорт проверяет состав, SHA-256 и возможность открытия ONNX перед заменой установленного комплекта.
3. «Камера» запрашивает CAMERA permission и начинает проверять заднюю камеру. Наведите её на человека. Для каждого лица отображаются рамка, «Соколов / не Соколов» и оценка модели.
4. «Фото» открывает системный выбор одного изображения. Приложение учитывает EXIF-поворот, находит все видимые лица и проверяет каждое. Доступ ко всей галерее не запрашивается.
5. Кнопка модели переключает ResNet18 / ArcFace. После переключения снова нажмите «Камера» или выберите фото.

Если хотя бы одно лицо превысило его validation-порог, общий результат — «Найден Соколов». При отсутствии найденных лиц явно сообщается «Лица не найдены»; это не доказательство отсутствия Соколова. Ошибки отдельных лиц также показаны отдельно. Оценка не объявляется калиброванной вероятностью.

Используются исходный SCRFD 640×640, NMS=.4 и те же пять ключевых точек и канонический шаблон ArcFace. Similarity transform выполняется Android Canvas, ресайз — Bitmap; возможны небольшие различия интерполяции относительно OpenCV/Pillow, поэтому качество всего мобильного тракта дополнительно проверяется на телефоне.

## Сборка

Проект в `android/`: Kotlin, CameraX, ONNX Runtime Android. Нужны JDK 17, Android SDK 35/Build Tools 34, Gradle wrapper 8.9.

```bash
cd android
./gradlew testDebugUnitTest assembleDebug
```

Либо откройте android/ в Android Studio и выберите Build APK. Путь APK: `android/app/build/outputs/apk/debug/app-debug.apk`. Локальный SDK задаётся через android/local.properties; этот файл не отправляется в Git.

## Проверка на Galaxy A35 после обучения

Проверить отдельно: разрешение/отказ камеры, повторный запуск после background, фото с EXIF 90°, отсутствие лица, несколько людей, новый негативный человек, отложенная фотография Соколова. На одном лице измерить частоту результатов после прогрева и затем после 2–3 минут работы для обеих моделей. Сравнить одинаковые фотографии в Python и в приложении; возможный сдвиг порога подбирать только на отдельной validation-выборке, не на test.

До появления обученных весов и проверки телефона реальные FPS и качество не измерены. Результаты локальных Python/ONNX и Android unit-тестов подтверждают реализацию/экспорт, но не заменяют эту проверку.

# Запуск на Kaggle GPU

Это инструкция для самостоятельного полного обучения. Разработка проверяется локально на небольшом искусственном наборе; готовых измерений качества ResNet18/ArcFace в репозитории нет.

## 1. Подготовить код

Самый простой способ запустить текущую локальную версию, даже до её отправки в GitHub:

```bash
python3 tools/package_kaggle.py
```

В `work/project_bundle.zip` попадут код, конфигурации, инструкция, ноутбук и уже опубликованные позитивы. Окружения, секреты, веса и результаты запусков в архив не включаются.

Создайте на Kaggle приватный Dataset с этим архивом. Создайте Notebook, импортируйте `notebooks/kaggle_train.ipynb` и подключите Dataset через **Add Input**. При отсутствии архива ноутбук клонирует main репозитория GitHub; этот вариант работает после отправки нового кода на GitHub.

В Settings включите GPU и Internet. Достаточно одной GPU; обучение моделей последовательное. Точные сроки зависят от доступной GPU и не гарантируются. Поддерживаемое окружение — Python 3.11/3.12; зафиксированные зависимости находятся в `requirements-kaggle.txt`. После установки перезапустите kernel, если этого требует Kaggle.

## 2. Предобученный ArcFace (WebFace600K, без ручных шагов)

Используется **официальный InsightFace ArcFace iResNet50, обученный на WebFace600K**, а не torchvision ResNet50. Это модель `w600k_r50.onnx` из пакета `buffalo_l`; из того же пакета берётся детектор SCRFD. Её веса точно переносятся в PyTorch-архитектуру arcface_torch `iresnet50` (`src/sokolov/backbones/iresnet.py`), поэтому градиенты по входной картинке для генерации сохраняются. Скачивать и подключать веса вручную не нужно. Если `model.checkpoint` указывает на отсутствующий файл `iresnet50_w600k.pt`, `check-weights`, `train` и `run-all` создают его автоматически. Отдельный запуск с численной проверкой:

```bash
python tools/convert_w600k_onnx.py --verify
```

Конвертер `tools/convert_w600k_onnx.py`:

- при отсутствии `checkpoints/insightface/models/buffalo_l/` скачивает `buffalo_l.zip` (288 621 354 байт, ≈275 MiB) из релиза InsightFace v0.7. Загрузка идёт через `sokolov.io.download` с таймаутом сокета 120 s и проверкой SHA-256 `80ffe37d8a5940d59a7384c201a2a38d4741f2f3c51eef46ebb28218a7b0ca2f`; у встроенного загрузчика `insightface` таймаута нет. Затем архив атомарно распаковывается в ту же папку, которую использует SCRFD. Если папка уже есть, сеть не используется;
- принимает только `w600k_r50.onnx` с SHA-256 `4c06341c33c2ca1f86781dab0e829f88ad5b64be9fba56e56bc9ebdefc619e43`;
- переносит все 237 инициализаторов по структуре графа. При экспорте в ONNX (PyTorch 1.9, opset 11) каждая пара Conv→BatchNorm свёрнута в Conv со смещением. Ядро записывается в Conv без смещения, а смещение — в следующий BatchNorm с mean=0, var=1−eps, weight=1. `bn1` блоков, `bn2`, `fc` и `features` хранятся в ONNX без свёртки и копируются как есть. Наклоны PReLU `(C,1,1)` приводятся к `(C,)`. Лишний узел или тензор и несовпадение формы или геометрии свёртки вызывают ошибку;
- сохраняет bare state_dict, который `build_model` загружает со `strict=True`, и рядом `iresnet50_w600k.json` с SHA-256 входа и выхода;
- сверяет отпечаток содержимого тензоров (`state_fingerprint`) со значением `970e13178e114fad152a3fce25c7a464144fc6a7412583126dcd3983dc62e294`.

Значения для `configs/arcface_face.toml`, `[model]`:

```toml
weights = "WebFace600K (InsightFace buffalo_l w600k_r50, converted)"
checkpoint = "checkpoints/arcface/iresnet50_w600k.pt"
checkpoint_sha256 = "8060e285754ba598293a466fe7fcff59713dbc3fc5305c2e36df595cab1e6cef"
```

SHA-256 файла получен с torch 2.5.1, как в `requirements-kaggle.txt`. Байты не зависят от имени файла, но `torch.save` другой версии PyTorch может дать другой хеш при том же содержимом.

Измерения: Apple M4, CPU, float32, torch 2.5.1, onnxruntime 1.20.1. Предобработка одинаковая: RGB, `(x − 127.5) / 127.5`. Так работает `ArcFaceONNX` в InsightFace, и это совпадает с нашим `ToTensor` + `Normalize(0.5, 0.5)`.

| Входы PyTorch и onnxruntime | Число | Max abs diff | Max abs выхода |
|---|---|---|---|
| Случайные, U(−1, 1) | 16 | 7.9e-6 | 1.78 |
| Лица Соколова, лекции 01/03/04/11: SCRFD → `align_face` → 112×112 | 16 | 2.0e-5 | 4.29 |
| Те же лица, эталон — `insightface` `get_feat` | 16 | 1.9e-5 | — |

Косинусное сходство эмбеддингов — это проверка здравого смысла, а не метрика качества:

- Соколов–Соколов из разных лекций: 96 пар, среднее 0.512, min 0.272, max 0.794;
- Соколов–другие люди: 96 пар, среднее −0.035, max 0.078. Использованы 6 лиц из примеров пакета `insightface`; изображения не сохраняются.

Ограничение: исходные статистики свёрнутых BatchNorm восстановить нельзя. В eval-режиме выход совпадает, но train-режим BatchNorm при дообучении всего backbone не воспроизводит исходную сеть. В конфигурации ArcFace `finetune_epochs = 0`, а замороженные слои остаются в eval.

Альтернатива — PyTorch `backbone.pth` iResNet50/MS1MV3 из Model Zoo [arcface_torch](https://github.com/deepinsight/insightface/tree/master/recognition/arcface_torch), он доступен через OneDrive или Baidu. Для неё задайте в `[model]` `weights = "MS1MV3"`, путь к файлу и его SHA-256 (`sha256sum backbone.pth`). Также поддержаны `model.checkpoint_url` (HTTPS) и обязательный для него `model.checkpoint_sha256`. Автоматически подменять веса другой моделью запрещено.

`check-weights` строго проверяет загрузку обеих моделей до загрузки FairFace и подготовки лиц. Отсутствующий или несовместимый checkpoint останавливает запуск; случайные веса вместо предобученных не используются. Веса ResNet18 скачиваются из официального Torchvision.

**Лицензия.** Предобученные модели InsightFace, включая `buffalo_l` и полученный из него checkpoint, разрешены только для некоммерческих исследований. Веса не публикуются вместе с кодом.

## 3. Данные и настройки

Наши 1000 позитивных кропов веб-камеры находятся в `data/raw/sokolov_positive_v1/`. Из них ещё выделяются лица. FairFace автоматически подключается через `kagglehub` по handle `mehmoodsheikh/fairface-dataset`. Можно добавить FairFace через Add Input и указать `FAIRFACE_DIR`, чтобы использовать уже подключённые файлы.

По умолчанию выбираются 5000 уникальных читаемых негативных изображений, seed=42. Версия, выбранные файлы и причины исключений записываются в `selection.local.json`. Для фиксации конкретной версии Kaggle можно изменить handle в обеих конфигурациях на `owner/dataset/versions/N`. Для локально подключённого набора сохраняются путь и хеши выбранных изображений; номер версии может быть недоступен.

Метки: `1=sokolov`, `0=not_sokolov`. Принадлежность позитивов принята по указанию владельца; негативы FairFace предполагаются другими людьми. Контактные листы и аудит позволяют проверить эту гипотезу; автоматический импорт не является независимой проверкой личности.

Обоим классам применяется один SCRFD и один алгоритм выравнивания. Единственное уверенно обнаруженное лицо сохраняется в RGB PNG 224×224; ArcFace использует уменьшение до 112×112. Пустые/неоднозначные кадры не попадают в обучение. Для итоговой image-level оценки сохранены все прошедшие исходный аудит test-изображения: отсутствие лица, несколько лиц и ошибка выравнивания приводят к отрицательному решению с отдельным статусом. Положительный пропуск считается FN.

Разбиение **случайное стратифицированное 70/15/15** до аугментаций. Для 6000 исходников без исключений: 4200/900/900. После детекции количество обучающих лиц может уменьшиться. Точные дубли RGB-пикселей удаляются до split; pHash — кандидаты для проверки, они автоматически не объявляются дублями. Лекции и возможные личности FairFace между выборками не изолированы: метрики могут быть завышены и не доказывают качество на новой лекции. Различие источников классов также может давать модели подсказки.

Один сохранённый split используется обеими моделями. При наличии `partition=train|test` у всех строк внешнего raw.csv назначения сохраняются: val выделяется из train по группам источников, test не меняется. Смешивать строки с назначенными и пустыми partition нельзя. Для внешнего набора используйте `split.mode="external"`.

## 4. Обучение и продолжение

Выполните ячейки ноутбука по порядку. Все записи создаются внутри `/kaggle/working/`, источники `/kaggle/input/` не изменяются. Конфиги обеих моделей должны иметь одинаковые настройки данных и split.

Команды из корня проекта:

```bash
python -m sokolov check-config
python -m sokolov check-weights --arcface-checkpoint /kaggle/input/my-arcface/backbone.pth
python -m sokolov run-all --run-dir /kaggle/working/runs/experiment-01 --arcface-checkpoint /kaggle/input/my-arcface/backbone.pth
```

Отдельные этапы доступны через `download-data`, `prepare`, `train`, `evaluate`, `report`. У `train` и `evaluate` одна модель определяется `--config configs/arcface_face.toml` или `configs/resnet18_face.toml`; у `run-all` обе конфигурации передаются через `--configs`.

Для продолжения добавьте `--resume` или установите `RESUME=True` в ноутбуке, не меняя RUN_ID и конфигурации. Восстанавливаются состояние модели, оптимизатора, номер эпохи и история. Изменение данных, split или параметров требует новых путей raw/prepared и нового RUN_ID. Кеши подготовки и выбранных файлов защищены отпечатками; не удаляйте только одну часть кеша.

Если Kaggle-сессия закончилась, сначала сохраните outputs через Save Version. Для продолжения в новой сессии подключите сохранённый output как Input и скопируйте весь каталог проекта/подготовленных данных и `runs/` обратно в те же пути `/kaggle/working/`; конфиги и абсолютные пути должны совпадать. Одних весов best.pt для продолжения недостаточно: нужен last.pt и данные подготовки.

## 5. Результаты и публикация

Выбор checkpoint — по AP на validation, при равенстве остаётся более ранний. Порог — по F1 на validation, при равенстве выбирается больший. Test не участвует в подборе.

Каталог запуска содержит:

- `data/`: аудит, split и сведения об источниках;
- `resnet18/`, `arcface/`: best.pt, last.pt, параметры, окружение, история, порог, метрики, test-предсказания, ошибки и локальные изображения ошибок;
- `report/`: Markdown, самостоятельный HTML со встроенными графиками, JSON/CSV и PNG.

Отчёт включает ROC-AUC, AP, accuracy, balanced accuracy, precision/recall/F1 по обоим классам, macro-F1, specificity, MCC, confusion matrix, log loss, Brier score, покрытие, время обучения, размер checkpoint и производительность. Скорость классификатора измеряется отдельно от детекции после прогрева с синхронизацией GPU. Неопределённые показатели обозначены N/A с причиной.

Публикация выполняется **отдельно после просмотра отчёта**. Добавьте в Kaggle Secrets токен `GITHUB_TOKEN` с Contents: write только для репозитория `nikitiva0/Sokolov-s-Classifier`. Запустите последнюю ячейку с `PUBLISH=True`. Команда отправляет отчёт в `reports/<RUN_ID>/` ветки main через отдельную временную копию репозитория. Публикуются только разрешённые агрегированные артефакты; изображения исходников, примеры ошибок, checkpoints, полные предсказания и секреты не отправляются. Force push не используется. Неполные и технические запуски отклоняются.

Локальный вариант после скачивания **всего каталога запуска**:

```bash
python -m sokolov publish-report --run-dir /absolute/path/experiment-01
```

Авторизация — существующее GitHub-подключение Git или переменная `SOKOLOV_GITHUB_TOKEN`. Не вставляйте токен в URL, исходники и ячейки. При ошибке публикации все локальные результаты сохраняются; устраните причину и повторите команду. Существующий RUN_ID в GitHub не перезаписывается.

## 6. Генерация из шума и лучшая модель

`run-all` теперь автоматически завершает задание генерацией. Сначала для каждой архитектуры сохраняется `best.pt` — лучшая эпоха по **validation AP**. Затем ResNet18 и ArcFace сравниваются по этому же показателю на общем validation. При равенстве выбирается ResNet18; test в выборе не участвует. Победитель копируется в **`<RUN_DIR>/best_model.pt`**, а название архитектуры, эпоха, AP и SHA-256 записываются в `best_model.json`.

Веса победителя фиксируются в eval-режиме. Из равномерного цветного шума оптимизируется непосредственно входная картинка: 224×224 для ResNet18 или 112×112 для ArcFace. Детектор и выравнивание в этот цикл не включаются. Нормализация берётся из сохранённого checkpoint.

Параметры `[generation]` в TOML:

- `steps=500`, `lr=0.05`, Adam изменяет только пиксели;
- цель: `logit − tv_weight × TV − l2_weight × mean((x−0.5)²)`;
- `tv_weight=0.0001`, `l2_weight=0.00001`, после каждого шага `x` ограничивается [0,1];
- пять начальных шумов: `seeds=[0,1,2,3,4]`;
- шаг 0, каждые 25 шагов и финал сохраняются как PNG.

Логит, sigmoid-оценка, TV, L2 и итоговая цель записываются на каждом шаге в `trajectory.csv`. Для точного соответствия картинкам эти показатели вычисляются по 8-битным пикселям PNG; сама оптимизация работает с непрерывными пикселями до округления. В метаданных проверяются диапазон пикселей, ненулевой конечный градиент и неизменность весов.

Файлы находятся в `<RUN_DIR>/synthesis/`: `seed_comparison.png`, общий график `scores.png`, `summary.json` и для каждого `seed_N/` — `final.png`, `snapshots/`, контактный лист `progression.png`, траектория и метаданные. Отчёт включает все начальные шумы, промежуточные шаги и графики. Синтетические изображения и траектории можно публиковать вместе с отчётом; файлы моделей остаются локальными.

Для уже завершённого обучения:

```bash
python -m sokolov select-best --run-dir /kaggle/working/runs/experiment-01
python -m sokolov synthesize --run-dir /kaggle/working/runs/experiment-01
python -m sokolov report --run-dir /kaggle/working/runs/experiment-01
```

`select-best` нужен только для старых запусков без `best_model.pt`; `synthesize` при необходимости вызовет его автоматически. Для дальнейшей генерации достаточно сохранить `best_model.pt` и `best_model.json` в одной папке. Обучение, фотографии и первоначальный checkpoint ArcFace повторно не нужны.

Другие ограничения и начальные шумы задаются через изменённый `[generation]` в отдельном TOML:

```bash
python -m sokolov synthesize --run-dir /path/to/run --generation-config configs/arcface_face.toml --output-dir /path/to/new-experiment --device cuda
```

Архитектура и нормализация всегда восстанавливаются из `best_model.pt`; из `--generation-config` берётся только раздел generation. Другие настройки требуют новой папки результата. Если процесс прервался, повторение той же команды использует завершённые seed и пересчитывает незавершённый. Повторно использовать каталог с другим checkpoint/настройками нельзя.

Узнаваемое лицо не гарантируется: возможны абстрактные узоры и повторяющиеся детали. Высокая оценка на синтетической картинке не подтверждает качество распознавания. Все пять результатов показываются без отбора, а график не обязан монотонно расти. Сравнение начальных шумов является дополнительным экспериментом из условия задания.

Разбиение данных осталось выбранным ранее случайным 70/15/15. Генерация не устраняет пересечения почти одинаковых кадров между train/test; для строгого выполнения требования задания об независимых фотографиях нужен отдельный split по лекциям и аудит похожих кадров.

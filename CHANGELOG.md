# История изменений

## 2026-10-31 — объединение v3 и ветки web-data-group-split

Статус: только код и конфигурации. Обучение объединённой версии не запускалось,
новых измерений качества нет. UI по умолчанию по-прежнему использует `local-mps-v2`.

- Исправление масштаба SCRFD (`shrink_only_top_left_pad_v1`) и проверка покрытия детектора
  действуют везде, включая сбор лиц и анализ генерации. Почти-дубликаты, исключённые из
  оценки, не считаются потерями детектора.
- Обработка `identity_v1` одинакова в обучении, оценке, UI, `predict` и во всех вариантах
  генерации (pixel / robust / fourier): классификатор видит ту же дифференцируемую маску и
  нормализацию; оценки PNG и анализ «похожести на лицо» используют её же.
- Один путь импорта данных: CSV дополнения v3 (`data.extra_manifest`) и манифесты HARVEST
  CONTRACT (`web_positive_v2`, `web_negative_v2`, `user_v3` с колонкой `partition`) читает
  одна функция. raw.csv и подготовленный манифест переведены на схему 3; старые кеши
  отклоняются, детекции можно переиспользовать через `reuse_prepared_manifest`.
- Одно групповое разбиение: группы по `group_id`, объединение pHash-связанных источников,
  стратификация по метке и домену; `train_only_sources` и ручные закрепления `user_v3`
  закрепляют группу целиком; гарантии обеих веток (лекция v1 и интернет-позитивы разных
  доменов в test, независимые интернет-группы обеих меток в validation/test, позитивная
  группа в validation, оба класса везде).
- Одна настройка аугментаций: `training.augmentation = "robust"` с параметрами `aug_*`
  (по умолчанию — рецепт v3; в `configs/*_face.toml` — рецепт web-data). Логический ключ
  `augment` удалён; старые checkpoint с ним читаются.
- Один критерий выбора (`source_macro_ap` или `average_precision`); семейства источников
  (лекции / интернет / FairFace) определяются одной функцией для балансировки, критерия
  выбора, метрик и аудита.
- `predict` использует код локального UI (`inference.py`); добавлены `--model`,
  `--detector-root`. Для ArcFace поддержаны MS1MV3 и конвертированный WebFace600K
  (`--arcface-weights`); переопределение файла весов снимает закреплённый в TOML хеш.
- Отчёт: доменные строки v3 в общей таблице с групповыми бутстрэп-ДИ, отдельные таблицы
  по доменам съёмки и источникам, протокол разбиения и защиты от почти-дубликатов.
- `configs/*_local_mps.toml` не изменены: собранные наборы в них не подключены, ResNet18
  дообучает только `layer4`, генерация — один вариант pixel. Ноутбук Kaggle передаёт
  `--download-fairface` и использует MS1MV3 только при подключённом `backbone.pth`.

Проверки: 76 тестов (обучение только на синтетических фикстурах); разбиение проверено на
локальных данных без детекции и обучения ([VALIDATION.md](docs/VALIDATION.md)).

## 2026-10-31 — v3: источники данных и аугментации

Статус: код и локальное дополнение датасета готовы. Новое обучение не запускалось,
новых измерений качества и обученных весов v3 нет. UI по умолчанию продолжает
использовать `local-mps-v2`.

### Изменения этого обновления

- Добавлена политика `identity_v1`: овальная маска лица, перевод в яркость,
  нормализация среднего и контраста внутри маски, эффективное разрешение 56×56.
  Обработка одинакова для обоих классов, обучения, проверки фото и генерации.
- Добавлен режим `robust`: отражение, поворот, сдвиг и масштаб, изменение цвета
  и яркости, уменьшение разрешения, размытие и JPEG-сжатие только в train.
- Добавлена балансировка источников при выборе train-примеров; соотношение
  классов и расчёт `pos_weight` по train сохраняются.
- По умолчанию используется `group_stratified`: целые лекции и источники,
  связанные pHash-кандидатами, получают один split. Доли 70/15/15 приблизительные.
- Пять пользовательских фото закреплены в train одной группой; похожие варианты
  наследуют это ограничение. При достаточном числе интернет-групп val/test
  получают минимум по две независимые группы каждой метки.
- Checkpoint и архитектура выбираются по среднему validation AP лекционных
  и интернет-позитивов. Порог — по validation F1 с весами источников.
  Test не используется для выбора. Добавлены доменные метрики в отчёт.
- Добавлены импорт дополнительного CSV и проверяемое повторное использование
  ранее подготовленных кропов. Старые checkpoint сохраняют исходную RGB-обработку.
- Подготовлено локальное дополнение: 14 позитивов (5 пользовательских + 9 публичных)
  и 8 негативов из интернет-источников. Общий raw-набор: 1014 позитивов и 5008 негативов.
- В Git добавлены каталог источников с метками, группами и хешами, координаты
  пользовательских кропов и `tools/build_domain_dataset.py`. Изображения дополнения
  и рабочий CSV остаются локальными; `tools/package_kaggle.py` включает их
  в приватный архив по точному списку CSV, без пользовательских оригиналов.
- Обновлены четыре TOML, оба ноутбука и инструкции. Новый локальный запуск
  сохраняется отдельно в `outputs/runs/domain-mps-v3/`; устройство строго `mps`.

Проверки: 31 тест без запуска цикла обучения; все 22 добавленных изображения
читаются и содержат одно обнаруженное лицо. Проверены восстановление кропов,
разбиение исходников и отсутствие найденных pHash-пар между выборками.
Это технические проверки, а не подтверждение качества будущих моделей.

### Актуальный функционал проекта

- Локальный веб-интерфейс для загрузки фото и проверки каждого найденного лица.
- Подготовка FairFace/позитивов, обучение ResNet18 и ArcFace на MPS или Kaggle GPU,
  сохранение и продолжение обучения.
- Выбор и сохранение лучшей модели; полный сравнительный отчёт и отдельная
  команда его публикации в GitHub.
- Генерация изображения из шума градиентной оптимизацией входа, визуализация
  шагов и сравнение пяти начальных шумов.

Для нового клона нужны зависимости, датасеты и checkpoint ArcFace; для UI —
готовый обученный запуск. Веса, FairFace и результаты обучения в Git не включаются.
Порядок восстановления дополнения: [DOMAIN_REPAIR.md](docs/DOMAIN_REPAIR.md).

## Предыдущее состояние — v2

Выполнено локальное обучение на Apple MPS после исправления масштаба SCRFD.
Созданы отчёт, генерация из шума и локальный UI. Android-приложение удалено.
Высокие метрики v2 получены на случайном разбиении кадров; они не подтверждают
перенос на новые лекции и интернет-фотографии и не являются результатами v3.

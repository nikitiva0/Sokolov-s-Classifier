# Данные: только лица

## Исходники

`data/raw/sokolov_positive_v1/` — опубликованные 1000 позитивных кропов веб-камеры, ещё требующих выделения лиц. Остальные локальные наборы игнорируются Git.

Команда `download-data` выбирает 5000 негативных изображений FairFace (`seed=42`), проверяя декодирование и совпадение RGB-пикселей. Результат по конфигам v3: `data/manifests/domain_v3/raw.csv` и `selection.local.json` с источником, версией при наличии, выбранными файлами, хешами и исключениями. Смешивать этот CSV со старым манифестом извлечения веб-камеры нельзя: разные схемы.

Raw CSV:

| Поле | Значение |
|---|---|
| image_id | Уникальный стабильный ID исходника |
| path | Абсолютный путь либо путь относительно рабочего корня проекта |
| label | `1=sokolov`, `0=not_sokolov` |
| source_id | Общая лекция/съёмка, для FairFace — исходный файл; это не гарантированный ID личности |
| source_url | Необязательная ссылка |
| partition | Пусто для первоначального split либо train/test для всех строк |
| pixel_sha256 | Для автоматического импорта — хеш размера и RGB-пикселей после EXIF-коррекции |

Лицо Соколова в позитивном наборе принято по разметке владельца. FairFace используется как негативный источник; визуальная проверка остаётся полезной. Неизвестную личность нельзя считать независимо подтверждённой одним именем файла.

## Аудит и split

До split проверяются метки, уникальность ID, декодирование и точные дубликаты. Повторные RGB-изображения одного класса удаляются; конфликтующие метки и пересечение точных дублей внешнего train/test — ошибка. 64-битный pHash находит кандидатов похожести (порог 6 бит); список сохраняется для проверки. В group_stratified источники, связанные такими парами, объединяются для назначения split; фотографии по pHash не удаляются.

По умолчанию: групповое разбиение, seed=42; целевые доли 65/15/20 в `configs/*_face.toml` и 70/15/15 в локальных MPS-конфигах. Единица — группа: `group_id` строки (лекция v1, видео, известный человек, файл FairFace; пустой `group_id` = `source_id`), группы, связанные pHash-кандидатами, объединяются. Группы стратифицируются по паре (метка группы, домен). Гарантии: оба класса в каждой выборке; в test — лекция v1 и интернет-позитивы двух доменов (если есть); при ≥ 3 независимых интернет-группах метки validation и test получают хотя бы по одной, при ≥ 5 — по две. Группа `web:user_provided_batch` (`split.train_only_sources`) и строки набора `user_v3` с колонкой `partition` закрепляют всю свою группу за train/test; незакреплённые строки той же группы наследуют закрепление, противоречивые закрепления — ошибка. Сводка: `split_summary.json`. Старый `random_stratified` поддержан для воспроизведения старого протокола, но закрепления с ним несовместимы.

Дополнение v3 добавляет 14 позитивов (5 пользовательских и 9 публичных) и 8 негативов. Каталог источников: `data/sources/domain_v3_sources.json`, локальный CSV: `data/manifests/domain_v3/web.csv`. [Восстановление и протокол](../docs/DOMAIN_REPAIR.md).

Все дополнительные наборы импортируются одной функцией `sokolov.data.download.import_manifest`, которая принимает два формата: CSV дополнения (`image_id,path,label,source_id,source_url`, необязательно `group_id,domain,person,timestamp_seconds`; ключ `data.extra_manifest`) и HARVEST CONTRACT ([HARVEST.md](../docs/HARVEST.md); каталоги `data.web_positive_dir`, `data.web_negative_dir`, `data.user_dir`). Из HARVEST берутся только строки `review_status=accepted`. raw.csv (схема 3) содержит `group_id, domain, dataset, person, timestamp_seconds, pinned_split`; старый raw.csv без этих колонок читается по префиксам `source_id` (`web:`, `fairface:`).

Если у всех исходников есть внешний partition, test сохраняется, val выделяется из train по группам source_id; группы внешних train/test не должны пересекаться. Нужны обе метки и достаточно групп. Смешанный CSV с пустыми и заполненными partition отклоняется. Обе модели используют один сохранённый `split.csv`; аугментации выполняются только после split, только для train.

## Подготовка

SCRFD из buffalo_l, threshold=0.5, input=640×640, CPUExecutionProvider. Пять ключевых точек совмещаются с каноническим шаблоном ArcFace через similarity transform. Обоим классам применяется один алгоритм. Сохраняется RGB PNG 224×224; модели используют 224 (ResNet18) и 112 (ArcFace).

`data/processed/domain_v3/manifest.csv` (схема 3) включает исходные поля, `group_id` (после объединения pHash-связанных групп), `domain`, `dataset`, `split`, `variant=face_crop`, `status`, `crop_path`, `crop_sha256`, `crop_phash`, `face_count`, `primary_face`, JSON с bbox/confidence/landmarks, время детекции и признак повторного использования детекции.

Статусы: `ok`, `no_face`, `alignment_failed`, `near_duplicate`. При нескольких лицах размечается лицо, bbox которого ближе всего к центру кадра (при равенстве — большее); остальные лица метку не получают. `near_duplicate` — лицо validation/test в пределах `split.dedup_max_distance` бит pHash выровненного кропа от лица train (лицо test — также от validation); такие строки не участвуют в оценке и не считаются потерями детектора в `min_detector_coverage`. Только `ok` допускается в обучение; необходимы обе метки в каждом split после детекции. Остальные исходники остаются в манифесте для полного image-level test и анализа покрытия.

`data_audit.json` сохраняет размеры на всех этапах, статусы, классы, исключения, pHash-кандидатов, пересечения источников, параметры/хеш детектора и время обработки. `prepared.json` связывает подготовку с хешами raw/prepared/split и конфигурацией. Смена параметров требует новой папки подготовки; повторное использование несовместимого кеша запрещено.

После сохранения RGB-кропа политика `identity_v1` одинаково для обоих классов применяет маску, нормализацию яркости/контраста и снижение эффективного разрешения. Она записывается в checkpoint; UI и генерация наследуют её. Аугментации выполняются только train.

## Оценка

Для единственного лица score фото равен score лица. Для остальных статусов — отрицательное решение с флагом; положительный пропуск учитывается как FN. Все исходные test-записи, прошедшие аудит до split, сохраняются в предсказаниях. Уровни image и face показываются отдельно.

Рабочие схемы расширяют минимальные шаблоны в `data/manifests/`. Актуальная информация об исходниках FairFace: https://github.com/joojs/fairface, CC BY 4.0.

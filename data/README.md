# Два варианта датасета: полный кадр и лицо

В проекте фиксированы `full_image` и `face_crop`. У каждого есть **train и test**.
Validation — внутренняя часть train для выбора checkpoint и порога; test в обучении
и подборе параметров не участвует.

## Единый исходный набор

Фотографии хранятся локально в `data/raw/`. Скопируйте
`data/manifests/manifest.example.csv` в `data/manifests/raw.csv` и заполните его.
Реальные фотографии и манифесты не попадают в Git.

| Поле | Смысл |
| --- | --- |
| `image_id` | Уникальный стабильный ID исходного кадра |
| `path` | Путь от корня проекта, например `data/raw/train/positive/photo.jpg` |
| `label` | `1`: нужный Евгений Соколов присутствует в кадре; `0`: отсутствует |
| `source_id` | Общая съёмка, мероприятие или исходное видео |
| `source_url` | Ссылка на источник; может быть пустой |
| `partition` | Внешняя часть: строго `train` или `test` |

Для действительно независимого снимка используйте отдельный `source_id`.
Не назначайте отдельную группу каждому кадру одного видео и не группируйте весь
датасет по домену сайта. Републикации одной съёмки получают общий `source_id`.

Перед разметкой зафиксируйте, о каком Евгении Соколове идёт речь, и проверьте
эталонные фото вручную. Совпадения имени недостаточно. Неопределённые случаи
отправляются на проверку, а не в отрицательный класс.
Добавьте разные фоны и ракурсы, других людей в сходных условиях и кадры без людей.

## Группировка и разделение

1. Проверить метки, ID, существование и декодирование файлов, EXIF-ориентацию.
2. Найти SHA-256-дубликаты и кандидатов в похожие кадры по 64-битному pHash.
3. Подтвердить похожие пары вручную и разрешить конфликты меток.
4. Построить общие `group_id`: связанные компоненты по источникам и дубликатам.
5. Проверить, что ни одна группа не пересекает внешние train/test.
   При конфликте остановить подготовку и исправить исходный набор явно.
6. Только внутри внешнего train выделить примерно 20% групп/снимков в val
   со стратификацией насколько позволяют группы, `seed=42`.
7. Сохранить общий `split.csv` на уровне исходных `image_id`; после этого
   построить full_image и face_crop, наследуя назначения.

Пропорции val приблизительные: целостность групп важнее точного процента.
В каждой части нужны оба класса и достаточно независимых групп.
Нельзя разбивать набор заново для каждой модели или после выделения лиц.
Все аугментации создаются после split и только в train.

Шаблон назначений: `data/manifests/splits.example.csv`.
Поля: `image_id,group_id,partition,split`; `partition` сохраняет внешний
train/test, а `split` принимает train/val/test. `partition=test` всегда означает
`split=test`; train может стать только train или val.

## Производные данные

Шаблон: `data/manifests/derived.example.csv`.

| Поле | Смысл |
| --- | --- |
| `sample_id` | Уникальный ID образца; для лиц отдельный на каждое лицо |
| `parent_image_id` | ID исходной фотографии из raw.csv |
| `path` | Путь к производному изображению |
| `label` | Метка именно этого образца |
| `source_id`, `group_id` | Наследуются от исходного изображения |
| `partition`, `split` | Наследуются из общего разбиения |
| `variant` | `full_image` или `face_crop` |

`full_image` сохраняет весь кадр и исходную метку. `face_crop` содержит
выделенные и выровненные по пяти точкам лица. Координаты лица, ключевые точки,
версия детектора и связь с родителем сохраняются в сопровождающих метаданных.
Общий crop строится один раз и затем масштабируется под модель: 224 для ResNet18,
112 для ArcFace. Детектор и его настройки фиксируются до финального test.

**Метка лица не копируется автоматически с фотографии.** На положительном
групповом снимке только лицо Соколова получает `1`, остальные люди получают `0`
после проверки. Неуверенно размеченные лица исключаются до обучения с записью
причины. Это не основание удалить исходную фотографию из итогового test.

Если лицо не найдено, фиксируем `no_face` на уровне исходной фотографии.
При оценке присутствия человека нельзя молча исключать такие кадры: положительный
кадр с пропущенным лицом должен учитываться как ошибка лицевого конвейера.
Полный набор test image_id сохраняется отдельно от таблицы успешно полученных crops.

## Сравнение

| Вариант | ResNet18 | ArcFace / iResNet50 |
| --- | --- | --- |
| Полный кадр | Да | Нет |
| Лицо | Да | Да |

Для сравнения encoder используйте одинаковые face crops. Для сравнения полного
кадра и лицевой системы считайте метрики на **одних исходных test-фотографиях**:
агрегируйте оценки лиц максимумом, отсутствие лица даёт отрицательное решение
с флагом `no_face`. Порог выбирается на validation с той же агрегацией.
Отдельно показывайте crop-метрики и долю кадров, на которых детектор нашёл лицо.
